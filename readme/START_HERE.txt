════════════════════════════════════════════════════════════════════════════════
                      🗄️ DATABASE STRUCTURE
════════════════════════════════════════════════════════════════════════════════

STUDENT TABLE (8 fields):
├─ student_id (Auto-increment Primary Key)
├─ name (Student's full name)
├─ roll_number (Unique identifier)
├─ class (Class and section, e.g., 11-A)
├─ email (Email address)
├─ phone (Phone number)
├─ address (Residential address)
└─ date_of_admission (Admission date)

FEE TABLE (7 fields):
├─ fee_id (Auto-increment Primary Key)
├─ student_id (Foreign Key - references student)
├─ total_fee (Total fee amount)
├─ paid_amount (Amount paid so far)
├─ pending_amount (Remaining amount)
├─ status (PAID/PENDING/PARTIAL)
└─ assigned_date (Date fee was assigned)

PAYMENT_RECORD TABLE (7 fields):
├─ payment_id (Auto-increment Primary Key)
├─ student_id (Foreign Key - references student)
├─ fee_id (Foreign Key - references fee)
├─ payment_amount (Payment amount)
├─ payment_date (Timestamp of payment)
├─ payment_method (Cash/Cheque/Online)
└─ remarks (Additional notes)

All tables use:
✓ Primary keys for unique identification
✓ Foreign keys for data relationships
✓ Cascading deletes for data integrity
✓ Proper indexing for performance
